# Faster zero-shot / few-shot runs

`fast_run/run_fast.py` runs `zero_shot/run_zero_shot.py` with three speed-ups. It does not change the original runner, and it writes to `results/fast_run/<lang>/`, so the original results stay as they are.

| Speed-up | What it does | Effect on results |
|---|---|---|
| Loop stop | Stops once the output ends in the same piece of text repeated 3+ times over 60+ characters | Only looping outputs, which are wrong anyway |
| Byte cap | Stops after `--max-bytes` bytes (default 1000; the longest gold answer is 819 bytes in Ainu) | Only outputs longer than any gold answer |
| `--dtype auto` | bfloat16 on A100 / L4, float32 on T4 | Tiny numerical differences from earlier float32 runs |

Simulation on the existing test outputs (the old outputs replayed through the new stop rule, no GPU): generated bytes drop by 67–71% for Ainu 3-shot and by 17–48% for zero-shot. The parsed answer changes in 3 of 6,676 normal (not truncated) rows: one looping gloss and two Ainu outputs over 1,000 bytes that copied long Japanese text. Script: `python fast_run/replay_loop_stop.py <result csv files> [--show]`.

Measured on a T4 (Ainu ICL all-in-one, same rows): 2.4× faster; of the 70 rows both runs finished, 68 outputs are identical and the 2 others are looping rows cut early.

New column `stop_reason`: `complete | loop | byte_cap | max_new_tokens | eos`. The `.meta.json` adds `stop_reason_counts`, `gold_answer_bytes_max` and the speed-up settings (under `generation.speedup`).

```
python fast_run/run_fast.py --lang ainu --split dev --limit 10                     # smoke test
python fast_run/run_fast.py --lang ainu --split test --shots 3 --resume            # full run
python fast_run/run_fast.py --lang ainu --split test --strategy all_in_one --resume
```

Options: `--max-bytes N`, `--no-loop-stop`, `--dtype {auto,float32,bfloat16}`, `--out-dir`; everything else is passed to `zero_shot/run_zero_shot.py`.
